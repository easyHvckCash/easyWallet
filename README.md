# easyWallet

An open-source research framework for reproducing known weak-entropy wallet vulnerabilities. Integrates published CVE proof-of-concepts with GPU-accelerated key derivation for academic verification and defensive auditing.

> **Disclaimer**: This project is intended solely for security research, academic study, and helping users verify whether their own wallets were generated by vulnerable software. Do not use this tool against wallets you do not own. The authors accept no liability for misuse.

**Live Demo**: A real-time instance of this framework is running at the project's [homepage](https://easyhackcash.auths.cloud/easywallet) — you can observe cluster status, scanning progress, and per-POC statistics from an actual single-node deployment.

## Reproduced Vulnerabilities

All POCs below correspond to publicly disclosed CVEs or security advisories. References link to the original disclosures.

| POC ID | Vulnerability | Effective Entropy | Derivation Speed | Affected Period | Reference |
|--------|--------------|-------------------|-----------------|-----------------|-----------|
| `dice_no_floor` | Coldcard dice path — no minimum entropy enforcement | 2.585N bit | ~50,000/s | 2017 ~ present | [Coldcard firmware](https://github.com/Coldcard/firmware) |
| `yasmarang_bypass` | Coldcard Mk3 TRNG fallback to Yasmarang PRNG | 32 bit | ~40,000/s | 2019 ~ 2020 | [Disclosure](https://github.com/nwfella/coldcard-entropy-incident) |
| `tw_wasm_mt19937` | TrustWallet WASM MT19937 single 32-bit seed | 32 bit | ~8,000/s | 2022-11 ~ 2023-04 | [CVE-2023-31290](https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2023-31290) |
| `tw_ios_minstd` | TrustWallet iOS minstd_rand0 LCG | 31 bit | ~40,000/s | 2018-03 ~ 2018-12 | [CVE-2024-23660](https://milksad.info/posts/research-update-5/) |
| `ill_bloom` | CryptoJS WordArray.random() MWC PRNG | ~39 bit | ~8,000/s | 2012 ~ 2023 | [CVE-2026-71851](https://blog.coinspect.com/) |

| `chosen_one` | Full 2^256 random sampling (control/baseline) | 256 bit | ~50,000/s | all time | BIP-39 standard |

## Background

A Bitcoin private key is a 256-bit random number with 2²⁵⁶ (≈1.16×10⁷⁷) possible values. When generated correctly, brute-force is computationally infeasible.

However, multiple wallet implementations have been found to use non-cryptographic PRNGs or insufficient entropy sources for key generation, reducing the effective keyspace to as little as 2³¹–2⁴⁰. These flaws have been publicly exploited, resulting in significant user losses documented in the CVEs above.

This framework enables researchers to:
- **Reproduce** published vulnerability findings independently
- **Verify** whether specific wallet generation methods are affected
- **Benchmark** GPU-accelerated key derivation performance
- **Audit** the effective entropy of wallet generation algorithms

## Quick Start

### 1. Obtain UTXO Address Set

**Option A: Deploy a Bitcoin full node**

1. Deploy an Ubuntu 24 VM
2. Run `dumpaddr/init.sh` to install Bitcoin Core and sync the blockchain
3. After sync, run `python3 dumpaddr/main.py` to export UTXO addresses

**Option B: Download pre-built set**

Download: https://mega.nz/file/T8BXBTyK#Vx2L3Qg1ue1ET5mgt5qvnNct2vgg_xy-tRUwTJh2p8o

Place the resulting `utxo_addresses.set` (~2.17GB) in `humanaction/addr/`.

---

### 2. Environment Setup

#### Windows 11

1. Install NVIDIA drivers: https://www.nvidia.com/en-us/drivers/
2. Install VS Build Tools:
```
.\vs_BuildTools.exe --wait --nocache --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended
```
3. Install CUDA Toolkit 12.x: https://developer.nvidia.com/cuda-downloads
4. Install Rust: https://rustup.rs/
5. Restart, then build:
```bash
build.bat
cd dist
```

Run master:
```bash
./btc-cuda-scanner.exe --role master --listenon 8877 --token mysecret --user admin --passwd admin
```

Run node:
```bash
./btc-cuda-scanner.exe --role node --server 127.0.0.1:8877 --token mysecret
```

Open http://localhost:8877/ for the dashboard.

#### Linux

```bash
chmod +x build.sh
./build.sh
cd dist
./btc-cuda-scanner --role master --listenon 8877 --token mysecret --user admin --passwd admin
```

---

### 3. Dashboard

1. **POC Test**: Generate mnemonic/privkey candidates from a selected POC algorithm
2. **Scanner**: Dispatch tasks to nodes for GPU-accelerated address matching
3. **Hit Records**: View matched addresses with source material and metadata
4. **Benchmark**: Verify detection accuracy against known test vectors

---

### 4. Adding POCs

Edit files under `humanaction/pocs/`:
- `pocinfo.json` — POC metadata
- `targets/<vendor>/<poc_id>/generator.py` — key generation script

Click **Reload** on the POC Test page after changes.
